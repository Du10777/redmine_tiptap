# Переводы редактора

Тексты редактора (подсказки тулбара, меню, диалоги, список языков кода, тексты вставляемых блоков) лежат не в JavaScript, а в файлах этой папки: по файлу на язык.

Редактор показывает их на языке, выбранном в профиле Redmine (Моя учётная запись → Язык). Тот, кто не вошёл в систему, получает язык, который Redmine подберёт для него: язык браузера, если он есть в Redmine, иначе язык Redmine по умолчанию. Если для языка нет файла, показывается английский; так же показывается любой текст, которого нет в файле.

| Файл | Язык |
|---|---|
| `en.yml` | Английский. Источник всех переводов: здесь есть каждый текст. |
| `ru.yml` | Русский. |

## Как добавить язык

1. Найдите код языка в [списке языков Redmine](#языки-redmine) ниже. Работают только эти коды: файл с любым другим кодом никогда не будет использован.
2. Скопируйте `en.yml` в `<код>.yml`, например `de.yml`.
3. Замените первую строку `en:` на `<код>:` (`de:`). Для норвежского пишите `"no":` в кавычках: YAML читает голое `no:` как слово «ложь».
4. Переведите значения, а ключи (слова перед двоеточием) оставьте как есть. Тексты оставьте в двойных кавычках. Первые символы пунктов списков (`☑`, `•`, `1.`, `a.`) — часть текста, их можно оставить. Тексты простые, HTML в них показывается как есть.
5. Проверьте файл, в папке Redmine:
   ```sh
   bundle exec rake redmine_tiptap:locales RAILS_ENV=production
   ```
6. Перезапустите Redmine.

Переводить всё сразу не обязательно: текст, которого нет или который оставлен пустым, показывается по-английски. Запустите проверку с `LOCALE=de`, чтобы увидеть, чего ещё не хватает в `de.yml`:

```sh
bundle exec rake redmine_tiptap:locales LOCALE=de RAILS_ENV=production
```

Проверка сообщает и о ключах, которых нет в `en.yml` (опечатка или удалённый текст), о файле, у которого первая строка не совпадает с именем, о коде, которого нет среди языков Redmine, и о неверном YAML. Если что-то найдено, она завершается с ошибкой, так что её можно запускать из скрипта.

Когда в плагине появляется новый текст, его добавляют в `en.yml` и `ru.yml`. Пока его нет в файле языка, он показывается по-английски; проверка выводит такие тексты списком.

## Языки с регионом

Язык с регионом сначала берёт язык без региона, а затем английский:

| Код | Берёт |
|---|---|
| `pt-BR` | `pt` |
| `zh-TW` | `zh` |
| `en-GB` | `en` |
| `es-PA` | `es` |
| `sr-YU` | `sr` |

Поэтому `pt` достаточно перевести один раз, а `pt-BR.yml` нужен только для текстов, которые в Бразилии звучат иначе. Учтите: у `zh-TW` (традиционный китайский) без своего файла показывается `zh` (упрощённый китайский), а не английский.

## Названия языков подсветки

Названия и подсказки языков кода (Python, SQL, ...) приходят из файлов языков в папке `highlight/`, по-английски. Файл перевода может изменить, как язык выглядит в списке и на ярлыке блока кода, и добавить слова, по которым язык находится в поиске; для этого нужен раздел `code_languages:` и `id` языка:

```yaml
de:
  redmine_tiptap:
    code_languages:
      routeros:
        label: "..."      # показывается вместо названия из highlight/routeros.js
        hint: "..."       # показывается вместо серой подсказки
        keywords: "..."   # дополнительные слова для поиска, к английским
```

Все три поля необязательные. Поиск по английским словам работает всегда. Настоящие примеры — в `ru.yml`. `id` должен совпадать с именем файла в `highlight/` (неверный проверка покажет).
