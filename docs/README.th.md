## Redmine เวอร์ชันที่รองรับ

| Redmine | รองรับ | ทดสอบบนเวอร์ชัน |
|---|---|---|
| 7.x | ใช่ | 7.0.2 |
| 6.x | ใช่ | 6.1.4, 6.1.5 |
| 5.x และเก่ากว่า | ไม่ | — |

เวอร์ชันหลักใหม่ (8.x ขึ้นไป) จะรองรับก็ต่อเมื่อได้ทดสอบปลั๊กอินบนเวอร์ชันนั้นแล้ว ก่อนหน้านั้น Redmine เวอร์ชันดังกล่าวจะไม่เริ่มทำงานเมื่อติดตั้งปลั๊กอินไว้ โดยจะหยุดพร้อมข้อผิดพลาดที่ระบุเวอร์ชันที่รองรับ

## ฟีเจอร์

### การจัดรูปแบบข้อความ
- ตัวหนา, ตัวเอียง, ขีดเส้นใต้, ขีดทับ, ตัวห้อยและตัวยก (Ctrl+, และ Ctrl+.), โค้ดในบรรทัด
- สีข้อความและสีพื้นหลัง: จานสี 64 สี หรือค่า hex ใดๆ
- แบบอักษร (13 แบบ) และขนาดแบบอักษร (ขนาดสำเร็จรูปตั้งแต่ 8 ถึง 72 px หรือค่าใดๆ ก็ได้)
- รูปแบบย่อหน้า: หัวเรื่อง 1–6 และข้อความปกติ
- การจัดแนว (ชิดซ้าย, กึ่งกลาง, ชิดขวา, ชิดขอบ) และการเยื้อง (สูงสุด 8 ระดับ) ของย่อหน้าและหัวเรื่อง
- ลิงก์: แทรก, แก้ไข, นำออก
- เส้นแนวนอน, เลิกทำและทำซ้ำ

### รายการ
- รายการสัญลักษณ์หัวข้อย่อยที่ใช้เครื่องหมายเป็นวงกลมทึบ วงกลมโปร่ง หรือสี่เหลี่ยม
- รายการลำดับเลข: 1, 01, a, A, i, I, α
- รายการงานพร้อมช่องทำเครื่องหมาย โดยงานที่เสร็จแล้วจะถูกขีดทับ
- รายการซ้อนกัน (Tab / Shift+Tab)

### ตาราง
- แทรกตารางขนาดใดๆ จะมีหรือไม่มีแถวส่วนหัวก็ได้
- เมนูคลิกขวาในเซลล์: เพิ่มและลบแถวและคอลัมน์, ผสานและแยกเซลล์, แถวส่วนหัวและคอลัมน์ส่วนหัว, ลบตาราง
- ปรับความกว้างของคอลัมน์ได้โดยลากขอบเซลล์
- การวางจาก Excel จะคงความกว้างของคอลัมน์ การจัดแนว และขนาดแบบอักษรไว้ ส่วนตารางที่คัดลอกจาก Redmine จะวางลงใน Excel พร้อมเส้นขอบ

### รูปภาพและไฟล์แนบ
- วางรูปภาพจากคลิปบอร์ด: ระบบจะอัปโหลดเป็นไฟล์แนบและแสดงในข้อความ
- รูปภาพที่แนบด้วยช่องแฟ้มของ Redmine หรือที่ลากมาวางบนช่องนั้น จะถูกแทรกลงในข้อความด้วยเช่นกัน
- แทรกรูปภาพจากไฟล์แนบ (ตัวเลือกแบบภาพขนาดย่อ) หรือลิงก์ไปยังไฟล์แนบใดๆ
- ปรับขนาดรูปภาพโดยลากที่มุมของรูป

### โค้ด
- บล็อกโค้ดที่มีการเน้นสีไวยากรณ์ทั้งในตัวแก้ไขและในหน้าที่จัดเก็บแล้ว: 52 ภาษา และเพิ่มได้อีก (ดู [การเน้นสีไวยากรณ์](#การเน้นสีไวยากรณ์))
- เลือกภาษาของบล็อกได้จากป้ายที่มุมของบล็อก โดยมีช่องค้นหา รวมถึงภาษาที่ใช้ล่าสุดและใช้บ่อย
- Tab และ Shift+Tab เพิ่มและลดการเยื้องของบรรทัดภายในบล็อกโค้ด ส่วนตัวหนา ลิงก์ และสีภายในโค้ดจะยังคงอยู่

### บล็อก
- บล็อกที่ยุบได้: หัวข้อที่มีเนื้อหาซ่อนอยู่ (`<details>`) ในหน้าที่จัดเก็บแล้วจะยุบอยู่ ส่วนในตัวแก้ไขจะขยายอยู่
- บล็อกคำอ้างอิงที่มีบรรทัดผู้เขียนและวันที่

### การแก้ไข
- โหมด `<HTML>` สำหรับดูและแก้ไขซอร์สโค้ด HTML: บล็อกที่ซ้อนกันจะถูกเยื้อง, บรรทัดว่างจะคั่นระหว่างบล็อกที่ยาวหลายบรรทัด, ไวยากรณ์จะถูกเน้นสีตามกฎเดียวกับบล็อกโค้ด HTML, และการกด Enter จะคงการเยื้องของบรรทัดไว้
- การพิมพ์แบบ Markdown: `#` สำหรับหัวเรื่อง, `-` และ `1.` สำหรับรายการ, `[ ]` สำหรับงาน, ```` ```python ```` สำหรับบล็อกโค้ด (ระบุชื่อภาษาใดก็ได้หรือไม่ระบุก็ได้), `**bold**`, `---` สำหรับเส้นแนวนอน แป้นพิมพ์ลัดมาตรฐาน: Ctrl+B, Ctrl+I, Ctrl+U, Ctrl+Z และอื่นๆ
- ตัวแก้ไขจะไม่สูงเกินกว่าหน้าต่าง: แถบเครื่องมือและปุ่มของฟอร์มจะอยู่ในมุมมองเสมอ และข้อความจะเลื่อนอยู่ภายใน ความสูงจะปรับตามขนาดหน้าต่างและการซูมหน้าเว็บ
- ที่จับปรับขนาดที่มุมขวาล่างใช้กำหนดความสูงด้วยตนเอง ระบบจะจำความสูงไว้ และการดับเบิลคลิกจะคืนเป็นความสูงอัตโนมัติ

### การผสานรวมกับ Redmine
- ใช้งานได้ในทุกช่องข้อความของ Redmine ที่รองรับการจัดรูปแบบ: รายละเอียดและบันทึกของปัญหา, หน้า Wiki, ข่าว, ข้อความในสภากาแฟ, เอกสาร, รายละเอียดของโครงการ, เขตข้อมูลแบบระบุเองชนิดข้อความขนาดยาว รวมถึงช่องที่ปรากฏบนหน้าในภายหลัง
- ข้อความจะถูกเก็บเป็น HTML หากต้องการใช้ตัวแก้ไข ให้เลือก *TipTap HTML* เป็นการจัดรูปแบบข้อความในหน้าปรับแต่งของ Redmine
- อินเทอร์เฟซ (คำแนะนำเครื่องมือ, เมนู, กล่องโต้ตอบ) ใช้ภาษาตามโปรไฟล์ Redmine ของผู้ใช้ ส่วนเสริมมาพร้อมกับ 47 จาก 50 ภาษาของ Redmine: ภาษาอังกฤษและภาษารัสเซียแปลครบถ้วน ส่วนอีก 45 ภาษาเป็นฉบับร่างที่จัดทำด้วยโมเดล AI ซึ่งยินดีให้เจ้าของภาษาช่วยแก้ไข ภาษาที่เขียนจากขวาไปซ้ายทั้งสามภาษา (อาหรับ, ฮีบรู, เปอร์เซีย) ไม่รองรับโดยเจตนา (ดู [ภาษาของอินเทอร์เฟซ](#ภาษาของอินเทอร์เฟซ))
- ยังคงทำงานได้เร็วกับข้อความขนาดใหญ่: ตัวแก้ไขในฟอร์มที่ซ่อนอยู่จะถูกสร้างเมื่อเปิดฟอร์มเท่านั้น และบล็อกโค้ดที่ยาวจะถูกเน้นสีเมื่อเลื่อนเข้ามาในมุมมอง
- ข้อความที่เขียนใน CKEditor (ปลั๊กอิน redmine_ckeditor) จะแสดงแบบเดิมและเปิดขึ้นในตัวแก้ไขพร้อมการจัดรูปแบบ: ไม่มีการแปลง ดู [การย้ายข้อมูลจาก CKEditor](#การย้ายข้อมูลจาก-ckeditor)
- ข้อความที่จัดเก็บแล้วจะแสดงโดยไม่มี HTML ที่ไม่ปลอดภัย: สคริปต์, ตัวจัดการเหตุการณ์ และลิงก์ `javascript:` จะถูกนำออกเมื่อแสดงหน้า โดยจะเก็บไว้เฉพาะสิ่งที่ตัวแก้ไขสร้างขึ้นเอง ซึ่งครอบคลุมข้อความที่เข้ามาทาง REST API หรือโหมด `<HTML>` ด้วย

## การเน้นสีไวยากรณ์

บล็อกโค้ดจะถูกเน้นสีเหมือนกันทั้งในตัวแก้ไขและในหน้าที่จัดเก็บแล้ว เลือกภาษาของบล็อกได้จากป้ายที่มุมขวาบนของบล็อก รายการภาษามีช่องค้นหาและจดจำภาษาที่ใช้ล่าสุดและใช้บ่อย

ส่วนเสริมมาพร้อมกับ 52 ภาษา ซึ่งรวมถึง HTML, 1C, Cisco IOS, MikroTik RouterOS, Windows cmd, docker compose, ล็อกบริการของ Linux และเอาต์พุตของ journalctl

สามารถเพิ่มภาษาของคุณเองได้ แต่ละภาษาคือไฟล์หนึ่งไฟล์ในโฟลเดอร์ `highlight/` ไวยากรณ์ใดๆ ของ highlight.js (190+ รายการ) หรือของบุคคลที่สาม แปลงเป็นไฟล์ดังกล่าวได้ด้วยคำสั่งเดียว:

```sh
python3 highlight/_convert_grammar.py erlang
sh highlight/_compile.sh
```

รายละเอียด: [highlight/README/th.md](../highlight/README/th.md)

## ภาษาของอินเทอร์เฟซ

ตัวแก้ไขจะแสดงเป็นภาษาที่เลือกไว้ในโปรไฟล์ Redmine ของผู้ใช้ (บัญชีของฉัน → ภาษา) ส่วนเสริมมาพร้อมไฟล์สำหรับ 47 จาก 50 ภาษาของ Redmine อยู่ใน `config/locales/` ภาษาอังกฤษเป็นต้นฉบับ ส่วนภาษารัสเซียเป็นฉบับที่ผู้เขียนจัดทำเอง อีก 45 ภาษาเป็นฉบับร่างที่จัดทำด้วยความช่วยเหลือของโมเดล AI และยังไม่ได้รับการตรวจทานจากเจ้าของภาษา จึงอาจพบสำนวนแปลกๆ อยู่บ้างเป็นบางจุด ข้อความที่ไม่มีอยู่ในไฟล์จะแสดงเป็นภาษาอังกฤษ

หากต้องการแก้ไขคำแปล ให้เปลี่ยนค่าใน `config/locales/<code>.yml` (`de`, `fr`, `pt-BR`, ...) แล้วรีสตาร์ต Redmine คำสั่ง `bundle exec rake redmine_tiptap:locales` จะตรวจสอบไฟล์เหล่านี้ ยินดีรับ pull request ที่มีการแก้ไข

**ภาษาที่เขียนจากขวาไปซ้าย (อาหรับ, ฮีบรู, เปอร์เซีย) ไม่รองรับโดยเจตนา** การรองรับภาษาเหล่านี้ต้องแก้ไขโค้ดเบสหลายส่วน ไม่ใช่เพียงการแปล และเราเลือกที่จะไม่ทำเช่นนั้น สำหรับภาษาเหล่านี้ ตัวแก้ไขจะแสดงเป็นภาษาอังกฤษและไม่มีการปรับเลย์เอาต์ หากต้องการภาษาใดภาษาหนึ่งในนี้ ให้สร้างฟอร์ก: กลไกการแปลพร้อมแล้ว และสิ่งอื่นที่ต้องเปลี่ยนแปลงมีระบุไว้ใน [config/locales/README.md](../config/locales/README.md#right-to-left-languages)

รายละเอียดและรายการภาษาของ Redmine: [config/locales/README.md](../config/locales/README.md)

## การติดตั้ง

1. วางส่วนเสริมไว้ในโฟลเดอร์ `plugins` ของ Redmine โดยโฟลเดอร์ต้องมีชื่อว่า `redmine_tiptap` วิธีที่ง่ายที่สุดคือใช้ git ซึ่งทำให้การอัปเดตเหลือเพียงคำสั่งเดียวด้วย:
   ```sh
   cd /path/to/redmine
   git clone --branch release --single-branch --depth 1 https://github.com/Du10777/redmine_tiptap.git plugins/redmine_tiptap
   ```
   สาขา `release` มีเฉพาะไฟล์ที่ปลั๊กอินต้องใช้ในการทำงาน ไม่มีเอกสารนี้ และ `--depth 1` จะไม่ดาวน์โหลดประวัติของที่เก็บ
2. รีสตาร์ต Redmine
3. ในหน้าปรับแต่งของ Redmine (redmine.selfhosted/_settings_) ให้เลือกการจัดรูปแบบข้อความเป็น *TipTap HTML*

## การอัปเดต

ส่วนเสริมนี้ไม่มี migration ของฐานข้อมูล และ JavaScript bundle กับสไตล์ชีตที่บิลด์แล้วเป็นส่วนหนึ่งของรีโพซิทอรี การอัปเดตจึงไม่ต้องใช้ทั้ง npm และการบิลด์บนเซิร์ฟเวอร์ เพียงแทนที่ไฟล์ของส่วนเสริมแล้วรีสตาร์ต Redmine

ก่อนอัปเดต ให้ตรวจสอบว่าเวอร์ชันใหม่รองรับ Redmine เวอร์ชันของคุณ (ดู "Redmine เวอร์ชันที่รองรับ" ด้านบน)

### ติดตั้งด้วย git (แนะนำ)

```sh
cd /path/to/redmine/plugins/redmine_tiptap
git pull
```

จากนั้นรีสตาร์ต Redmine เช่น:

```sh
sudo systemctl restart redmine          # Redmine ที่ทำงานเป็นบริการ systemd
touch /path/to/redmine/tmp/restart.txt  # Passenger
docker compose restart redmine          # Docker
```

หากต้องการอยู่ที่เวอร์ชันใดเวอร์ชันหนึ่งแทนเวอร์ชันล่าสุด ให้ดึงคอมมิตของสาขา `release` แล้วสลับไปที่คอมมิตนั้น: `git fetch --depth 1 origin <commit> && git checkout <commit>`

หากติดตั้งปลั๊กอินด้วย `git clone` แบบธรรมดา (สาขา `main` ที่มีเอกสารและประวัติทั้งหมด) ให้ย้ายไปใช้สาขา `release` เพียงครั้งเดียว: ลบโฟลเดอร์ `plugins/redmine_tiptap` แล้วติดตั้งปลั๊กอินใหม่ตามที่อธิบายไว้ใน [การติดตั้ง](#การติดตั้ง) ปลั๊กอินไม่ได้เก็บข้อมูลของตนเองไว้ในโฟลเดอร์ จึงไม่มีอะไรสูญหาย ยกเว้นภาษาสำหรับการเน้นสีโค้ดที่คุณเพิ่มเอง ซึ่งต้องคัดลอกออกจาก `highlight/` ก่อน

### ติดตั้งจากไฟล์เก็บถาวร

1. ดาวน์โหลด `redmine_tiptap.zip` จากรุ่นล่าสุด: https://github.com/Du10777/redmine_tiptap/releases/latest/download/redmine_tiptap.zip ภายในมีไฟล์เดียวกับสาขา `release` (ปลั๊กอินโดยไม่มีเอกสารนี้) ลบโฟลเดอร์ `plugins/redmine_tiptap` เดิม แล้วแตกไฟล์เก็บถาวรลงในตำแหน่งเดียวกัน โฟลเดอร์ข้างในชื่อ `redmine_tiptap` อยู่แล้ว การลบก่อนช่วยให้แน่ใจว่าไฟล์ที่ถูกนำออกไปในเวอร์ชันใหม่จะไม่ตกค้างอยู่
2. ลบ `public/assets/.manifest.json` ในโฟลเดอร์ Redmine
3. รีสตาร์ต Redmine

ขั้นตอนที่ 2 สำคัญ เมื่อเริ่มทำงาน Redmine จะเผยแพร่ assets ของส่วนเสริมใหม่ก็ต่อเมื่อไฟล์เหล่านั้นใหม่กว่า manifest นี้ ไฟล์ที่แตกออกมาจากไฟล์เก็บถาวรจะคงเวลาแก้ไขเดิมไว้ ดังนั้นหากไม่ทำขั้นตอนที่ 2 Redmine อาจยังคงส่งตัวแก้ไขเวอร์ชันเก่าให้ผู้ใช้อยู่ ไฟล์ manifest จะถูกสร้างขึ้นใหม่โดยอัตโนมัติเมื่อเริ่มทำงาน เมื่อใช้ `git pull` ไม่จำเป็นต้องทำขั้นตอนนี้ เพราะ git จะกำหนดเวลาปัจจุบันให้กับไฟล์ที่เปลี่ยนแปลง

### หลังการอัปเดต

- URL ของสคริปต์และสไตล์ชีตของตัวแก้ไขมีค่าแฮชของเนื้อหาอยู่ด้วย ดังนั้นเบราว์เซอร์จึงโหลดเวอร์ชันใหม่ได้ทันทีหลังรีสตาร์ต ผู้ใช้ไม่ต้องล้างแคชของเบราว์เซอร์
- หากเปิดใช้ *แคชข้อความที่จัดรูปแบบ* ในหน้าปรับแต่งของ Redmine (บริหารจัดการ → ปรับแต่ง → ทั่วๆ ไป) ให้ล้างแคชของ Redmine หนึ่งครั้งหลังอัปเดตเป็นเวอร์ชันที่เปลี่ยนแปลงวิธีการแสดงข้อความ (การทำความสะอาด HTML, การรองรับข้อความจาก CKEditor): `bundle exec rake tmp:cache:clear RAILS_ENV=production` ในโฟลเดอร์ Redmine มิฉะนั้นหน้าที่เรนเดอร์ไว้ก่อนการอัปเดตอาจถูกแสดงจากแคชโดยไม่ได้ทำความสะอาด จนกว่าข้อความของหน้านั้นจะเปลี่ยนแปลง
- ส่วนเสริมเวอร์ชันก่อนหน้าคัดลอกสคริปต์ไปไว้ที่ `public/tiptap_bundle.js` ไฟล์เหล่านี้ไม่ได้ใช้งานแล้วและสามารถลบได้:
  ```sh
  rm -f /path/to/redmine/public/tiptap_bundle.js /path/to/redmine/public/tiptap_bundle.js.map
  ```

## การย้ายข้อมูลจาก CKEditor

หากใช้ [redmine_ckeditor](https://github.com/a-ono/redmine_ckeditor) กับ Redmine ของคุณ คุณสามารถเปลี่ยนไปใช้ปลั๊กอินนี้ได้พร้อมกับการเก็บข้อความที่เขียนมาแล้วทั้งหมด: ปัญหา, บันทึก, หน้า Wiki, ข่าว, ข้อความ, เอกสาร ไม่มีการแปลงและฐานข้อมูลจะไม่ถูกแก้ไข CKEditor และปลั๊กอินนี้ต่างก็เก็บข้อความเป็น HTML เหมือนกัน ดังนั้นข้อความที่เก็บไว้จะเพียงแค่แสดงโดยการจัดรูปแบบชุดใหม่

1. ติดตั้งปลั๊กอิน (ดูด้านบน) และเลือก การจัดรูปแบบข้อความ: *TipTap HTML*
2. เก็บโฟลเดอร์ `public/system/rich/` ของ Redmine ไว้ หากมีการแทรกรูปภาพและไฟล์ด้วยเบราว์เซอร์รูปภาพของ CKEditor ไฟล์เหล่านั้นจะถูกเก็บไว้ที่นั่น ไม่ได้เก็บในฐานข้อมูลและไม่ได้อยู่ในไฟล์แนบ และข้อความจะอ้างอิงถึงไฟล์เหล่านั้นด้วยที่อยู่ (`/system/rich/...`) **หากย้าย Redmine ไปยังเซิร์ฟเวอร์เครื่องอื่นหรือติดตั้งใหม่ ให้ย้ายโฟลเดอร์นี้ไปด้วย** พร้อมกับฐานข้อมูลและโฟลเดอร์ `files/`: ทั้งสองอย่างไม่ได้เก็บไฟล์เหล่านี้ไว้ และหากไม่มีโฟลเดอร์นี้ รูปภาพในข้อความเก่าจะแสดงข้อผิดพลาด 404 ไฟล์แนบของปัญหา, หน้า Wiki เป็นต้น จะเก็บเหมือนเดิมและไม่ต้องทำอะไรเพิ่มเติม รูปภาพที่แทรกด้วยตัวแก้ไขนี้เป็นไฟล์แนบทั่วไป โฟลเดอร์นี้ยังคงจำเป็นแม้จะลบ redmine_ckeditor ออกแล้ว
3. ลบ redmine_ckeditor ออกเมื่อคุณไม่ต้องการใช้อีกต่อไป

ข้อความเก่าจะแสดงแบบที่ CKEditor แสดงมา: แบบอักษร, ขนาด, สี และการจัดแนว, การเยื้อง, รายการ, ตาราง (เส้นขอบ, ความกว้าง, คำบรรยาย, เซลล์ที่ผสาน), รูปภาพ (ขนาด, float, เส้นขอบ, รูปภาพในลิงก์), ลิงก์, บล็อกโค้ดพร้อมภาษา (เน้นสี), แมโคร Redmine (`{{toc}}`, `{{collapse(Title) ... }}`, `{{thumbnail(...)}}` เป็นต้น), ลิงก์ wiki และลิงก์ปัญหา, ที่อยู่เว็บธรรมดาที่ถูกทำให้คลิกได้, และ `<iframe>` ฝังตัว (วิดีโอ) ข้อความที่เขียนใน CKEditor จะตรวจสอบโดยหลักการทำเครื่องหมายและคงการเว้นวรรคระหว่างย่อหน้าที่มีอยู่ที่นั่นไว้ ซึ่งกว้างกว่าในตัวแก้ไขนี้

ความแตกต่างโดยเจตนา:
- `<iframe>` จะแสดงเมื่อชี้ไปยังไซต์อื่นผ่าน http(s) เท่านั้น และมีการแยกได้: หน้าภายในสามารถเรียกใช้สคริปต์ของตัวเองได้ แต่ไม่สามารถเข้าหน้า Redmine, เปิดหน้าต่างด้านบน หรือส่งแบบฟอร์มได้ `<iframe>` อื่นๆ ทั้งหมดจะถูกลบออก
- ลิงก์เปิดในหน้าต่างเดียวกัน: แอตทริบิวต์ `target` ของลิงก์ (CKEditor's "New Window (_blank)") จะไม่เก็บไว้
- การจัดรูปแบบบางส่วนที่ CKEditor เสนอแต่หน้าของมันลบออกอย่างเงียบ ๆ จะแสดงที่นี่: เช่น สีพื้นหลังของสไตล์ "Marker" และเครื่องหมายอัญประกาศของ `<q>`
- สไตล์ “Special Container” ของ CKEditor (บล็อกที่มีกรอบสีเทา) จะแสดงเป็นบล็อกโค้ดที่ไม่มีการเน้นสี และในตัวแก้ไขก็เป็นบล็อกโค้ดเช่นกัน

ข้อความเก่าจะเก็บการจัดรูปแบบไว้เมื่อเปิดในตัวแก้ไขและบันทึกอีกครั้ง: แมโคร Redmine (แมโครเป็นองค์ประกอบสีเทาหนึ่งในตัวแก้ไข; แก้ไขในโหมด `<HTML>` เหมือน Source mode ของ CKEditor), `<iframe>`, บล็อก `<div>` และ `<address>` พร้อมสไตล์ของบล็อกเหล่านั้น (`<div>` ที่วางจากหน้าเว็บยังคงถูกแปลงเป็นย่อหน้า), ตัวห้อยและตัวยก, สไตล์อินไลน์ของ CKEditor (big, small, keyboard, sample เป็นต้น), สไตล์ของหัวเรื่อง, ตาราง และเซลล์ตาราง, ขนาด (ความกว้างและความสูง), float, เส้นขอบ และลิงก์ของรูปภาพ, ภาษาของบล็อกโค้ด สิ่งที่ไม่คงอยู่หลังการแก้ไข: คำบรรยายของตารางกลายเป็นย่อหน้าที่จัดกึ่งกลางเหนือตาราง, ส่วนหัวและส่วนท้ายของตารางกลายเป็นแถวทั่วไป (ส่วนท้ายอยู่ที่ด้านล่าง) และ `<del>` กลายเป็น `<s>` (มีหน้าตาเหมือนกัน) ข้อความที่บันทึกจากตัวแก้ไขนี้จะมีการเว้นวรรคย่อหน้าที่กระชับของตัวแก้ไขนี้
