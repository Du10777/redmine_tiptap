# Подсветка синтаксиса: языки

[English version](en.md)

Блоки кода раскрашиваются и в редакторе, и на сохранённых страницах (задачи, примечания, вики) — одинаково. Язык блока выбирается по ярлыку в его правом верхнем углу. Список языков задают файлы папки `highlight/`: один файл — один язык.

С плагином идут 52 языка. Можно добавить свои: перенести готовую грамматику из highlight.js скриптом (раздел [«Как добавить язык из highlight.js»](#как-добавить-язык-из-highlightjs)) или написать свою.

## Как это устроено

- Раскрашивает [highlight.js](https://highlightjs.org) (через [lowlight](https://github.com/wooorm/lowlight)). Движок один и тот же в редакторе и в просмотре, поэтому цвета совпадают.
- `_compile.sh` собирает все файлы языков в один файл `assets/javascripts/tiptap_highlight.js`. Он лежит в репозитории уже собранным, так что при установке плагина ничего собирать не нужно. Собирать нужно, только если вы меняете набор языков.
- Redmine подключает `tiptap_highlight.js` на каждой странице, раньше редактора (`tiptap_bundle.js`). Редактор при загрузке регистрирует все языки из этого файла.
- В редакторе блок перекрашивается через 50 мс после паузы в наборе, причём только изменившийся блок. В просмотре блок раскрашивается, когда доходит до экрана. Блок внутри свёрнутого спойлера раскрашивается, когда спойлер раскроют.
- Язык хранится в сохранённом HTML: `<pre><code class="language-<id>">`. Поэтому `id` языка менять нельзя: блоки, сохранённые со старым `id`, станут обычным текстом.
- Автоопределения языка нет: блок без языка показывается обычным текстом. Блок с языком, которого нет в `highlight/` (например, файл языка удалили), — тоже, а на его ярлыке остаётся `id`. Если файл языка вернуть, цвета вернутся.
- Цвета. highlight.js размечает текст классами `hljs-keyword`, `hljs-string`, `hljs-comment` и т. д. Цвета для них заданы в `assets/stylesheets/src/06_code.css` — та же палитра, что у подсветки самого Redmine.

## Файл языка

Например, `routeros.js`:

```js
import grammar from 'highlight.js/lib/languages/routeros';

export default {
  id: 'routeros',
  label: 'RouterOS',
  hint: 'MikroTik',
  keywords: 'mikrotik микротик',
  grammar: grammar,
};
```

| Поле | Обязательное | Что это |
|---|---|---|
| `id` | да | Имя языка в сохранённом HTML (`class="language-<id>"`). Допустимы `a-z`, `0-9`, `-`, `_`. **Не менять** после того, как блоки с этим языком сохранены. |
| `label` | нет | Название в списке языков и на ярлыке блока. По умолчанию — `id`. |
| `hint` | нет | Серая подсказка рядом с названием в списке. |
| `keywords` | нет | Дополнительные слова для поиска в списке, через пробел, на любом языке. |
| `grammar` | да | Грамматика highlight.js: функция `(hljs) => описание языка`. |

Какие файлы бывают в папке:

- **Короткий.** Ссылка на грамматику из npm-пакета highlight.js, как в примере выше; так сделана большая часть языков. Грамматика берётся из той версии highlight.js, что записана в `package-lock.json` плагина.
- **Полная копия.** Код грамматики лежит прямо в файле, его можно править. Такие файлы создаёт скрипт переноса (см. ниже).
- **Своя грамматика.** `log.js`, `journalctl.js`, `cisco-ios.js`; общие куски для них лежат в `_common.js`.
- **Обёртка.** Готовая грамматика под другим именем: `cmd.js` — это `dos` из highlight.js, `docker-compose.js` — это `yaml`.

Файлы и папки, чьё имя начинается с `_`, — не языки:

- `_compile.sh` — сборка;
- `_check.mjs` — проверка языков при сборке;
- `_common.js` — общие куски для своих грамматик;
- `_hljs/` — файлы, которые импортируют перенесённые грамматики (папку создаёт скрипт переноса).

Папка `README/` — эта документация и скрипт переноса `convert_hljs_language.py`.

## Как добавить язык из highlight.js

Готовые грамматики (их больше 190) лежат здесь: https://github.com/highlightjs/highlight.js/tree/main/src/languages. Названия и псевдонимы перечислены в [SUPPORTED_LANGUAGES.md](https://github.com/highlightjs/highlight.js/blob/main/SUPPORTED_LANGUAGES.md); там же есть около сотни сторонних грамматик из отдельных репозиториев. Любую из них переносит в формат плагина скрипт `README/convert_hljs_language.py`.

Скрипту нужен Python 3.6+ (без сторонних пакетов) и доступ к github.com. Запускать его надо из папки плагина:

```sh
cd /path/to/redmine/plugins/redmine_tiptap
python3 highlight/README/convert_hljs_language.py erlang
sh highlight/_compile.sh
```

Аргумент `erlang` — имя файла в `src/languages` без `.js`. Вторая команда собирает языки с проверкой. Затем перезапустите Redmine (см. [«Сборка и применение»](#сборка-и-применение)). В Windows вместо `python3` пишите `py` или `python`.

Примеры:

```sh
# список языков highlight.js (* — уже есть в highlight/), можно с фильтром по слову
python3 highlight/README/convert_hljs_language.py --list
python3 highlight/README/convert_hljs_language.py --list sql

# несколько языков сразу
python3 highlight/README/convert_hljs_language.py erlang nix fsharp

# своё название, подсказка и слова для поиска (только для одного языка за раз)
python3 highlight/README/convert_hljs_language.py erlang --label "Erlang/OTP" --hint BEAM --keywords "erl otp эрланг"

# заменить короткий файл из комплекта полной копией, которую можно править
python3 highlight/README/convert_hljs_language.py routeros --force --label RouterOS --hint MikroTik --keywords "mikrotik микротик"

# язык, которого ещё нет в выпущенной версии highlight.js, — из ветки разработки
python3 highlight/README/convert_hljs_language.py odin --ref main

# ссылка на файл грамматики — прямо из адресной строки браузера
python3 highlight/README/convert_hljs_language.py https://github.com/highlightjs/highlight.js/blob/main/src/languages/odin.js

# сторонняя грамматика: ссылка на репозиторий, файл грамматики скрипт найдёт сам
python3 highlight/README/convert_hljs_language.py https://github.com/highlightjs/highlightjs-terraform

# локальный файл грамматики
python3 highlight/README/convert_hljs_language.py ~/grammars/mylang.js --id mylang

# короткий файл со ссылкой на npm-пакет вместо копии кода
python3 highlight/README/convert_hljs_language.py erlang --npm

# посмотреть, что будет сделано, ничего не меняя
python3 highlight/README/convert_hljs_language.py erlang --dry-run
```

### Что делает скрипт

1. Скачивает `src/languages/<имя>.js` той версии highlight.js, на которой работает плагин. Версия берётся из `package-lock.json` (сейчас 11.12.0): грамматики пишутся под движок своей версии. Другую версию, ветку или коммит задаёт `--ref`.
2. Название языка берёт из строки `Language:` в заголовке грамматики, слова для поиска — из её псевдонимов (`aliases`). `id` — имя файла грамматики.
3. Кладёт код грамматики в `highlight/<id>.js` без изменений, кроме экспорта: `export default function(hljs)` превращается в `function grammar(hljs)`, а в конец файла дописывается объект языка `export default { id, label, keywords, grammar }`. Если грамматика написана как модуль CommonJS (`module.exports = ...`), в начало добавляется строка с `module` и `exports`.
4. Если грамматика импортирует другие файлы, скачивает их в `highlight/_hljs/<источник>-<версия>/` по тем же путям, что в репозитории, и направляет туда импорты. Например, `typescript` импортирует `javascript.js` и `lib/ecmascript.js`. Эти файлы общие для всех языков из того же источника и той же версии; править их не нужно.
5. Проверяет строку `Requires:` — языки, которыми размечается вложенный код (например, `php-template` нужны `xml` и `php`). Если их нет в `highlight/`, подсказывает команду, которой их добавить. Без них вложенный код просто остаётся без цвета, ошибкой это не считается.
6. Не перезаписывает существующие файлы без `--force` и не берёт `id`, который уже занят другим файлом.

После переноса язык можно править прямо в его файле.

### Параметры

| Параметр | Что делает |
|---|---|
| `ЯЗЫК ...` | Имя языка из highlight.js, ссылка на файл грамматики или на репозиторий сторонней грамматики на GitHub, путь к локальному `.js`. |
| `--ref REF` | Версия (тег), ветка или коммит highlight.js. По умолчанию — версия из `package-lock.json`. Для ссылок версия берётся из самой ссылки. |
| `--id ID` | `id` языка. По умолчанию — имя файла грамматики. |
| `--label ТЕКСТ` | Название в списке и на ярлыке. По умолчанию — `Language:` из грамматики. |
| `--hint ТЕКСТ` | Серая подсказка в списке. |
| `--keywords ТЕКСТ` | Слова для поиска через пробел. По умолчанию — псевдонимы грамматики. |
| `--npm` | Вместо копии кода — короткий файл со ссылкой на npm-пакет highlight.js. Только для языков самого highlight.js. |
| `--force` | Заменять существующие файлы. |
| `--dry-run` | Показать, что будет сделано, ничего не меняя. |
| `--list [СЛОВО]` | Список языков highlight.js и сторонних грамматик, можно с фильтром по слову. |
| `--prune` | Удалить из `_hljs/` файлы, которые больше не импортирует ни один язык. |

Сообщения скрипт пишет по-русски или по-английски — по языку системы.

**Копия или `--npm`?** Копия показывает правила прямо в файле: их можно править, можно взять грамматику новее установленного пакета или стороннюю. Копия не меняется при обновлении highlight.js в плагине; чтобы обновить её, перенесите язык заново с `--force`. Файл с `--npm` занимает несколько строк, а грамматика в нём обновляется вместе с плагином.

## Сборка и применение

```sh
sh highlight/_compile.sh
```

- Нужен Docker (сборка идёт в контейнере `node:20-alpine`) или, если Docker нет, Node.js 18+ на этой машине. В первый раз скрипт сам ставит npm-пакеты в папку `node_modules/` плагина.
- Сначала скрипт проверяет каждый язык: собирает его отдельно, загружает, регистрирует в том же движке, что работает в браузере, и раскрашивает пробный текст. Если язык сломан (ошибка в коде, неверное регулярное выражение, занятый `id`), скрипт называет файл и причину и останавливается, а прежний `tiptap_highlight.js` остаётся на месте.
- Затем скрипт собирает все языки в `assets/javascripts/tiptap_highlight.js`.

После сборки перезапустите Redmine: файлы плагинов он публикует при старте (команды — в разделе «Updating» [главного README](../../README.md#updating)). Браузеры получат новый файл сразу, потому что в его адресе есть отпечаток содержимого.

Если на сервере Redmine нет ни Docker, ни Node.js, соберите на любой машине, где они есть: достаточно копии папки плагина. Готовый `assets/javascripts/tiptap_highlight.js` положите на сервер.

## Как убрать язык

Удалите файл языка из `highlight/`, соберите и перезапустите Redmine. Сохранённые блоки этого языка останутся как есть и будут показаны обычным текстом. Файлы в `_hljs/`, которые больше никому не нужны, убирает команда:

```sh
python3 highlight/README/convert_hljs_language.py --prune
```

## Свои грамматики и правка правил

- Грамматика — это функция, которая получает объект `hljs` и возвращает описание языка: какие куски текста как размечать. Руководство: https://highlightjs.readthedocs.io/en/latest/language-guide.html, справочник: https://highlightjs.readthedocs.io/en/latest/mode-reference.html. Примеры — `log.js`, `journalctl.js`, `cisco-ios.js`.
- highlight.js склеивает регулярные выражения всех правил языка в одно и игнорирует их собственные флаги. Поэтому нечувствительность к регистру пишется явно (`[Ee]rror`) или включается для всего языка: `case_insensitive: true`.
- Классы токенов лучше брать стандартные (`keyword`, `string`, `number`, `comment`, `title`, `attr`, `variable`, `built_in`, `literal`, `meta`, `symbol`, `type` и т. д.) — для них уже есть цвета. Для своего класса (например, `scope: 'log-error'` даёт класс `hljs-log-error`) нужно правило в `assets/stylesheets/src/06_code.css` и пересборка CSS (`assets/stylesheets/src/_build.sh`).
- Готовую грамматику под другим именем делают как `cmd.js`: вызывают исходную и меняют в результате `name` и `aliases`. Без замены псевдонимов новый язык перехватит их у исходного.

## Обновление плагина, если вы добавляли языки

Ваши файлы в `highlight/` git не тронет. Но `assets/javascripts/tiptap_highlight.js` в новой версии плагина собран без ваших языков, а ваша сборка этого файла помешает `git pull`. Поэтому:

```sh
cd /path/to/redmine/plugins/redmine_tiptap
git checkout -- assets/javascripts/tiptap_highlight.js
git pull
sh highlight/_compile.sh
```

Первая команда убирает вашу сборку, последняя собирает языки заново вместе с вашими. После этого перезапустите Redmine. Если вы правили файлы языков из комплекта, git может попросить разрешить конфликт в них.

Если плагин поставлен из архива, сохраните свои файлы языков и папку `_hljs/` перед заменой папки плагина, верните их после и соберите языки.

## Размер

Все языки собираются в один файл; браузер загружает его один раз, дальше берёт из кэша. Сейчас это 226 КБ на 52 языка. Большинство языков весит 1–10 КБ, самый большой — 1С (55 КБ).
