> *คำแปลนี้จัดทำโดยใช้โมเดล AI ช่วย และยังไม่ได้รับการตรวจทานจากเจ้าของภาษา หากพบข้อผิดพลาด โปรด [เปิด issue หรือส่ง pull request](https://github.com/Du10777/redmine_tiptap)*

บล็อกโค้ดจะถูกเน้นสีทั้งในตัวแก้ไขและในหน้าที่จัดเก็บแล้ว (ปัญหา, บันทึก, หน้า Wiki) และมีหน้าตาเหมือนกันทั้งสองที่ เลือกภาษาของบล็อกได้จากป้ายที่มุมขวาบนของบล็อก รายการภาษากำหนดโดยไฟล์ในโฟลเดอร์ `highlight/` โดยหนึ่งไฟล์คือหนึ่งภาษา

ส่วนเสริมมาพร้อมกับ 52 ภาษา และเพิ่มได้อีก: แปลงไวยากรณ์สำเร็จรูปของ highlight.js ด้วยสคริปต์ (ดู [การเพิ่มภาษาจาก highlight.js](#การเพิ่มภาษาจาก-highlightjs)) หรือเขียนไวยากรณ์ขึ้นเอง

## วิธีการทำงาน

- การเน้นสีทำโดย [highlight.js](https://highlightjs.org) (ผ่าน [lowlight](https://github.com/wooorm/lowlight)) ตัวแก้ไขและหน้าที่จัดเก็บแล้วใช้เอนจินเดียวกัน สีจึงตรงกัน
- `_compile.sh` รวมไฟล์ภาษาทั้งหมดไว้ในไฟล์เดียวคือ `assets/javascripts/tiptap_highlight.js` ไฟล์นี้ถูกคอมมิตลงรีโพซิทอรีในสถานะที่บิลด์เสร็จแล้ว การติดตั้งส่วนเสริมจึงไม่ต้องบิลด์ ต้องบิลด์ก็ต่อเมื่อเปลี่ยนชุดของภาษาเท่านั้น
- Redmine โหลด `tiptap_highlight.js` ในทุกหน้า ก่อนตัวแก้ไข (`tiptap_bundle.js`) เมื่อโหลดขึ้นมา ตัวแก้ไขจะลงทะเบียนทุกภาษาจากไฟล์นั้น
- ในตัวแก้ไข บล็อกจะถูกเน้นสีใหม่ 50 ms หลังจากที่หยุดพิมพ์ และจะทำเฉพาะบล็อกที่เปลี่ยนแปลงเท่านั้น ในหน้าที่จัดเก็บแล้ว บล็อกจะถูกเน้นสีเมื่อเลื่อนเข้ามาในมุมมอง ส่วนบล็อกที่อยู่ในส่วนที่ยุบไว้จะถูกเน้นสีเมื่อเปิดส่วนนั้นออก
- ภาษาถูกเก็บไว้ใน HTML ที่จัดเก็บ: `<pre><code class="language-<id>">` ด้วยเหตุนี้ `id` ของภาษาจึงต้องไม่เปลี่ยนแปลงเด็ดขาด เพราะบล็อกที่จัดเก็บไว้ด้วย `id` เดิมจะกลายเป็นข้อความธรรมดา
- ไม่มีการตรวจจับภาษาอัตโนมัติ: บล็อกที่ไม่ระบุภาษาจะแสดงเป็นข้อความธรรมดา บล็อกที่ใช้ภาษาซึ่งไม่อยู่ใน `highlight/` ก็เช่นเดียวกัน (เช่น ไฟล์ภาษาถูกลบไป) โดยป้ายของบล็อกยังคงแสดง `id` อยู่ หากไฟล์ภาษากลับมา สีก็จะกลับมาด้วย
- สี: highlight.js ทำเครื่องหมายข้อความด้วยคลาสต่างๆ เช่น `hljs-keyword`, `hljs-string`, `hljs-comment` สีของคลาสเหล่านี้กำหนดไว้ใน `assets/stylesheets/src/06_code.css` โดยใช้จานสีของการเน้นสีไวยากรณ์ของ Redmine เอง

## ไฟล์ภาษา

ตัวอย่างเช่น `routeros.js`:

```js
import grammar from 'highlight.js/lib/languages/routeros';

export default {
  id: 'routeros',
  label: 'RouterOS',
  hint: 'MikroTik',
  keywords: 'mikrotik',
  grammar: grammar,
};
```

| ฟิลด์ | จำเป็น | คืออะไร |
|---|---|---|
| `id` | ใช่ | ชื่อภาษาใน HTML ที่จัดเก็บ (`class="language-<id>"`) อักขระที่อนุญาต: `a-z`, `0-9`, `-`, `_` **ห้ามเปลี่ยนเด็ดขาด** เมื่อมีการจัดเก็บบล็อกที่ใช้ภาษานี้แล้ว |
| `label` | ไม่ | ชื่อในรายการภาษาและบนป้ายของบล็อก ค่าเริ่มต้นคือ `id` |
| `hint` | ไม่ | หมายเหตุสีเทาที่อยู่ข้างชื่อในรายการ |
| `keywords` | ไม่ | คำเพิ่มเติมสำหรับการค้นหาในรายการ คั่นด้วยช่องว่าง |
| `grammar` | ใช่ | ไวยากรณ์ของ highlight.js: ฟังก์ชัน `(hljs) => language definition` |

`label`, `hint` และ `keywords` เป็นภาษาอังกฤษ หากต้องการให้แสดงภาษาด้วยชื่ออื่นในภาษาของอินเทอร์เฟซของผู้ใช้ หรือให้ค้นหาภาษานั้นพบด้วยคำของภาษานั้น ให้เพิ่มรายการลงในไฟล์คำแปลของภาษานั้น คือ `config/locales/<code>.yml` ภายใต้ `code_languages:` คำที่ใส่ไว้ตรงนั้นจะถูกเพิ่มเข้าไปใน `keywords` ส่วน `label` และ `hint` จะแทนที่ค่าจากไฟล์ภาษา ตัวอย่างมีอยู่ใน `config/locales/ru.yml` ส่วนกฎต่างๆ อยู่ใน [config/locales/README.md](../../config/locales/README.md)

ชนิดของไฟล์ในโฟลเดอร์:

- **แบบสั้น:** การอ้างอิงถึงไวยากรณ์จากแพ็กเกจ npm ของ highlight.js ดังตัวอย่างข้างต้น ภาษาส่วนใหญ่เป็นแบบนี้ ไวยากรณ์จะมาจากเวอร์ชันของ highlight.js ที่ระบุไว้ใน `package-lock.json` ของส่วนเสริม
- **สำเนาเต็ม:** โค้ดของไวยากรณ์อยู่ในไฟล์นั้นเองและแก้ไขได้ ไฟล์ประเภทนี้สร้างโดยสคริปต์แปลง (ดูด้านล่าง)
- **ไวยากรณ์ที่เขียนเอง:** `log.js`, `journalctl.js`, `cisco-ios.js` ส่วนที่ใช้ร่วมกันอยู่ใน `_common.js`
- **ตัวห่อหุ้ม:** ไวยากรณ์สำเร็จรูปที่ใช้ภายใต้ชื่ออื่น: `cmd.js` คือ `dos` จาก highlight.js และ `docker-compose.js` คือ `yaml`

ไฟล์และโฟลเดอร์ที่มีชื่อขึ้นต้นด้วย `_` ไม่ใช่ภาษา:

- `_compile.sh` บิลด์ภาษาทั้งหมด
- `_check.mjs` ตรวจสอบภาษาระหว่างการบิลด์
- `_common.js` เก็บส่วนที่ใช้ร่วมกันของไวยากรณ์ที่เขียนเองของส่วนเสริม
- `_convert_grammar.py` คือสคริปต์ที่แปลงไวยากรณ์ของ highlight.js (ดูด้านล่าง)
- `_vendor/` เก็บไฟล์ที่ไวยากรณ์ที่แปลงแล้วนำเข้า (สร้างโดยสคริปต์แปลง)

โฟลเดอร์ `README/` เก็บเอกสารนี้

## การเพิ่มภาษาจาก highlight.js

ไวยากรณ์สำเร็จรูป (มากกว่า 190 รายการ) อยู่ที่นี่: https://github.com/highlightjs/highlight.js/tree/main/src/languages ชื่อและชื่อเรียกอื่นของไวยากรณ์เหล่านี้มีรายการอยู่ใน [SUPPORTED_LANGUAGES.md](https://github.com/highlightjs/highlight.js/blob/main/SUPPORTED_LANGUAGES.md) พร้อมด้วยไวยากรณ์ของบุคคลที่สามอีกราวหนึ่งร้อยรายการที่เก็บไว้ในรีโพซิทอรีแยกต่างหาก สคริปต์ `_convert_grammar.py` ในโฟลเดอร์นี้สามารถแปลงไวยากรณ์เหล่านี้ตัวใดก็ได้ให้เป็นรูปแบบของส่วนเสริม

สคริปต์ต้องใช้ Python 3.6+ (ไม่ต้องติดตั้งแพ็กเกจเพิ่มเติม) และต้องเข้าถึง github.com ได้ ให้รันสคริปต์จากโฟลเดอร์ของส่วนเสริม:

```sh
cd /path/to/redmine/plugins/redmine_tiptap
python3 highlight/_convert_grammar.py erlang
sh highlight/_compile.sh
```

อาร์กิวเมนต์ `erlang` คือชื่อไฟล์ใน `src/languages` โดยไม่มี `.js` คำสั่งที่สองบิลด์ภาษาและตรวจสอบภาษาเหล่านั้น จากนั้นรีสตาร์ต Redmine (ดู [การบิลด์และการนำไปใช้](#การบิลด์และการนำไปใช้)) บน Windows ให้ใช้ `py` หรือ `python` แทน `python3`

ตัวอย่าง:

```sh
# รายการภาษาของ highlight.js (* = มีอยู่ใน highlight/ แล้ว) จะกรองด้วยคำก็ได้
python3 highlight/_convert_grammar.py --list
python3 highlight/_convert_grammar.py --list sql

# หลายภาษาพร้อมกัน
python3 highlight/_convert_grammar.py erlang nix fsharp

# ชื่อ คำใบ้ และคำค้นหาที่กำหนดเอง (ครั้งละหนึ่งภาษา)
python3 highlight/_convert_grammar.py erlang --label "Erlang/OTP" --hint BEAM --keywords "erl otp"

# แทนที่ไฟล์แบบสั้นที่มาพร้อมกับส่วนเสริมด้วยสำเนาเต็มที่แก้ไขได้
python3 highlight/_convert_grammar.py routeros --force --label RouterOS --hint MikroTik --keywords mikrotik

# ภาษาที่ยังไม่มีใน highlight.js เวอร์ชันที่เผยแพร่แล้ว โดยดึงจากสาขาพัฒนา
python3 highlight/_convert_grammar.py odin --ref main

# ลิงก์ไปยังไฟล์ไวยากรณ์ คัดลอกจากแถบที่อยู่ของเบราว์เซอร์มาใช้ได้เลย
python3 highlight/_convert_grammar.py https://github.com/highlightjs/highlight.js/blob/main/src/languages/odin.js

# ไวยากรณ์ของบุคคลที่สาม: ลิงก์ไปยังรีโพซิทอรีของไวยากรณ์นั้น สคริปต์จะหาไฟล์ไวยากรณ์ให้เอง
python3 highlight/_convert_grammar.py https://github.com/highlightjs/highlightjs-terraform

# ไฟล์ไวยากรณ์ในเครื่อง
python3 highlight/_convert_grammar.py ~/grammars/mylang.js --id mylang

# ไฟล์แบบสั้นที่อ้างอิงแพ็กเกจ npm แทนการคัดลอกโค้ด
python3 highlight/_convert_grammar.py erlang --npm

# แสดงสิ่งที่จะทำโดยไม่เปลี่ยนแปลงอะไรเลย
python3 highlight/_convert_grammar.py erlang --dry-run
```

### สคริปต์ทำอะไรบ้าง

1. ดาวน์โหลด `src/languages/<name>.js` ของ highlight.js เวอร์ชันที่ส่วนเสริมใช้งานอยู่ เวอร์ชันนี้อ่านจาก `package-lock.json` (ปัจจุบันคือ 11.12.0) เพราะไวยากรณ์ถูกเขียนขึ้นสำหรับเอนจินของเวอร์ชันของตัวเอง ตัวเลือก `--ref` ใช้เลือกเวอร์ชัน สาขา หรือคอมมิตอื่น
2. นำชื่อภาษามาจากบรรทัด `Language:` ในส่วนหัวของไวยากรณ์ และนำคำค้นหามาจากชื่อเรียกอื่นของไวยากรณ์ (`aliases`) ส่วน `id` คือชื่อไฟล์ไวยากรณ์
3. วางโค้ดของไวยากรณ์ลงใน `highlight/<id>.js` โดยไม่เปลี่ยนแปลงอะไรนอกจากส่วน export: `export default function(hljs)` จะกลายเป็น `function grammar(hljs)` และอ็อบเจกต์ภาษา `export default { id, label, keywords, grammar }` จะถูกต่อท้ายไว้ที่ท้ายไฟล์ หากไวยากรณ์เป็นโมดูล CommonJS (`module.exports = ...`) จะมีการเพิ่มบรรทัดที่ประกาศ `module` และ `exports` ไว้ที่ด้านบนสุด
4. หากไวยากรณ์นำเข้าไฟล์อื่น จะดาวน์โหลดไฟล์เหล่านั้นไปไว้ใน `highlight/_vendor/<source>-<version>/` โดยใช้พาธเดียวกับในรีโพซิทอรี และชี้การนำเข้าไปที่นั่น ตัวอย่างเช่น `typescript` นำเข้า `javascript.js` และ `lib/ecmascript.js` ไฟล์เหล่านี้ใช้ร่วมกันโดยทุกภาษาจากแหล่งและเวอร์ชันเดียวกัน จึงไม่จำเป็นต้องแก้ไข
5. ตรวจสอบบรรทัด `Requires:` ซึ่งระบุภาษาที่ใช้สำหรับโค้ดที่ฝังอยู่ (เช่น `php-template` ต้องใช้ `xml` และ `php`) หากภาษาเหล่านั้นไม่อยู่ใน `highlight/` จะแสดงคำสั่งสำหรับเพิ่มภาษาเหล่านั้น หากไม่มีภาษาเหล่านั้น โค้ดที่ฝังอยู่จะเพียงแค่ไม่มีสี ซึ่งไม่ถือเป็นข้อผิดพลาด
6. ไม่เขียนทับไฟล์ที่มีอยู่แล้วหากไม่ใช้ `--force` และไม่ใช้ `id` ที่ไฟล์อื่นใช้อยู่แล้ว

หลังการแปลง สามารถแก้ไขภาษาได้ในไฟล์ของภาษานั้นโดยตรง

### ตัวเลือก

| ตัวเลือก | หน้าที่ |
|---|---|
| `LANGUAGE ...` | ชื่อภาษาของ highlight.js, ลิงก์ไปยังไฟล์ไวยากรณ์หรือไปยังรีโพซิทอรีไวยากรณ์ของบุคคลที่สามบน GitHub หรือพาธไปยังไฟล์ `.js` ในเครื่อง |
| `--ref REF` | เวอร์ชัน (แท็ก), สาขา หรือคอมมิตของ highlight.js ค่าเริ่มต้นคือเวอร์ชันใน `package-lock.json` สำหรับลิงก์ จะใช้เวอร์ชันจากลิงก์นั้น |
| `--id ID` | `id` ของภาษา ค่าเริ่มต้นคือชื่อไฟล์ไวยากรณ์ |
| `--label TEXT` | ชื่อในรายการและบนป้าย ค่าเริ่มต้นคือ `Language:` จากไวยากรณ์ |
| `--hint TEXT` | หมายเหตุสีเทาในรายการ |
| `--keywords TEXT` | คำค้นหาที่คั่นด้วยช่องว่าง ค่าเริ่มต้น: ชื่อเรียกอื่นของไวยากรณ์ |
| `--npm` | แทนที่จะคัดลอกโค้ด ให้เขียนไฟล์แบบสั้นที่อ้างอิงแพ็กเกจ npm ของ highlight.js ใช้ได้เฉพาะกับภาษาของ highlight.js เอง |
| `--force` | แทนที่ไฟล์ที่มีอยู่แล้ว |
| `--dry-run` | แสดงสิ่งที่จะทำโดยไม่เปลี่ยนแปลงอะไร |
| `--list [WORD]` | แสดงรายการภาษาของ highlight.js และไวยากรณ์ของบุคคลที่สาม โดยจะกรองด้วยคำก็ได้ |
| `--prune` | ลบไฟล์ใน `_vendor/` ที่ไม่มีภาษาใดนำเข้าอีกต่อไป |


**สำเนา หรือ `--npm`?** สำเนาจะแสดงกฎต่างๆ ไว้ในไฟล์เลย: แก้ไขกฎเหล่านั้นได้ ใช้ไวยากรณ์ที่ใหม่กว่าแพ็กเกจที่ติดตั้งไว้ หรือใช้ไวยากรณ์ของบุคคลที่สามก็ได้ สำเนาจะไม่เปลี่ยนไปเมื่อส่วนเสริมอัปเกรด highlight.js หากต้องการให้เป็นปัจจุบัน ให้แปลงภาษานั้นอีกครั้งด้วย `--force` ส่วนไฟล์ที่สร้างด้วย `--npm` จะมีความยาวเพียงไม่กี่บรรทัด และไวยากรณ์ของไฟล์จะอัปเกรดไปพร้อมกับส่วนเสริม

## การบิลด์และการนำไปใช้

```sh
sh highlight/_compile.sh
```

- ต้องใช้ Docker (การบิลด์ทำงานในคอนเทนเนอร์ `node:20-alpine`) หรือหากไม่มี Docker ให้ใช้ Node.js 18+ บนเครื่องเดียวกัน ในการรันครั้งแรก สคริปต์จะติดตั้งแพ็กเกจ npm ลงในโฟลเดอร์ `node_modules/` ของส่วนเสริม
- ก่อนอื่นสคริปต์จะตรวจสอบทุกภาษา: บิลด์ภาษานั้นแยกต่างหาก โหลดภาษานั้น ลงทะเบียนในเอนจินเดียวกับที่ทำงานในเบราว์เซอร์ และเน้นสีข้อความตัวอย่าง หากภาษาใดมีปัญหา (โค้ดผิดพลาด, regular expression ไม่ถูกต้อง, `id` ถูกใช้ไปแล้ว) สคริปต์จะระบุชื่อไฟล์และสาเหตุแล้วหยุดทำงาน โดย `tiptap_highlight.js` ตัวก่อนหน้าจะยังคงอยู่ที่เดิม
- จากนั้นสคริปต์จะรวมทุกภาษาไว้ใน `assets/javascripts/tiptap_highlight.js`

หลังจากบิลด์แล้ว ให้รีสตาร์ต Redmine เพราะ Redmine จะเผยแพร่ไฟล์ของส่วนเสริมเมื่อเริ่มทำงาน (ดูคำสั่งได้ที่ "การอัปเดต" ใน [README หลัก](../../docs/README.th.md#การอัปเดต)) เบราว์เซอร์จะได้รับไฟล์ใหม่ทันที เพราะ URL ของไฟล์มีค่าแฮชของเนื้อหารวมอยู่ด้วย

หากเซิร์ฟเวอร์ Redmine ไม่มีทั้ง Docker และ Node.js ให้บิลด์บนเครื่องใดก็ได้ที่มีอย่างใดอย่างหนึ่งในสองอย่างนี้ (เพียงสำเนาของโฟลเดอร์ส่วนเสริมก็เพียงพอ) แล้วนำไฟล์ `assets/javascripts/tiptap_highlight.js` ที่ได้ไปวางบนเซิร์ฟเวอร์

## การลบภาษา

ลบไฟล์ภาษาออกจาก `highlight/` บิลด์ใหม่ แล้วรีสตาร์ต Redmine บล็อกที่จัดเก็บไว้ด้วยภาษานี้จะคงอยู่ตามเดิมและแสดงเป็นข้อความธรรมดา ไฟล์ใน `_vendor/` ที่ไม่จำเป็นอีกต่อไปจะลบได้ด้วยคำสั่ง:

```sh
python3 highlight/_convert_grammar.py --prune
```

## ไวยากรณ์ที่เขียนเองและกฎการแก้ไข

- ไวยากรณ์คือฟังก์ชันที่รับอ็อบเจกต์ `hljs` และคืนค่านิยามภาษา ซึ่งระบุว่าจะทำเครื่องหมายข้อความส่วนใดและทำอย่างไร คู่มือ: https://highlightjs.readthedocs.io/en/latest/language-guide.html เอกสารอ้างอิง: https://highlightjs.readthedocs.io/en/latest/mode-reference.html ตัวอย่าง: `log.js`, `journalctl.js`, `cisco-ios.js`
- highlight.js จะรวม regular expression ของทุกกฎในภาษาหนึ่งเข้าเป็นนิพจน์เดียว และจะไม่สนใจแฟล็กของแต่ละนิพจน์เอง ดังนั้นการจับคู่แบบไม่สนใจตัวพิมพ์ใหญ่-เล็กจึงต้องเขียนระบุให้ชัดเจน (`[Ee]rror`) หรือเปิดใช้กับทั้งภาษาด้วย `case_insensitive: true`
- ควรใช้คลาสโทเค็นมาตรฐาน (`keyword`, `string`, `number`, `comment`, `title`, `attr`, `variable`, `built_in`, `literal`, `meta`, `symbol`, `type` เป็นต้น) เพราะคลาสเหล่านี้มีสีกำหนดไว้แล้ว ส่วนคลาสที่สร้างขึ้นเอง (เช่น `scope: 'log-error'` จะสร้างคลาส `hljs-log-error`) ต้องมีกฎใน `assets/stylesheets/src/06_code.css` และต้องบิลด์ CSS ใหม่ (`assets/stylesheets/src/_build.sh`)
- หากต้องการเสนอไวยากรณ์สำเร็จรูปภายใต้ชื่ออื่น ให้ทำตามที่ `cmd.js` ทำ คือเรียกไวยากรณ์ต้นฉบับ แล้วเปลี่ยน `name` และ `aliases` ในผลลัพธ์ หากไม่ได้แทนที่ชื่อเรียกอื่น ภาษาใหม่จะรับชื่อเหล่านั้นมาจากต้นฉบับ

## การอัปเดตส่วนเสริมเมื่อได้เพิ่มภาษาไว้แล้ว

git จะไม่แตะต้องไฟล์ของคุณใน `highlight/` แต่ `assets/javascripts/tiptap_highlight.js` ในส่วนเสริมเวอร์ชันใหม่ถูกบิลด์มาโดยไม่มีภาษาของคุณ และไฟล์นี้ที่คุณบิลด์ไว้เองจะขัดขวาง `git pull` ดังนั้นให้ทำดังนี้:

```sh
cd /path/to/redmine/plugins/redmine_tiptap
git checkout -- assets/javascripts/tiptap_highlight.js
git pull
sh highlight/_compile.sh
```

คำสั่งแรกจะทิ้งไฟล์ที่คุณบิลด์ไว้ ส่วนคำสั่งสุดท้ายจะบิลด์ภาษาทั้งหมดใหม่อีกครั้ง รวมถึงภาษาของคุณ จากนั้นรีสตาร์ต Redmine หากคุณแก้ไขไฟล์ภาษาที่มาพร้อมกับส่วนเสริม git อาจขอให้คุณแก้ไขข้อขัดแย้งในไฟล์เหล่านั้น

หากติดตั้งส่วนเสริมจากไฟล์เก็บถาวร ให้เก็บสำรองไฟล์ภาษาของคุณและโฟลเดอร์ `_vendor/` ไว้ก่อนแทนที่โฟลเดอร์ของส่วนเสริม จากนั้นนำกลับมาวางไว้ที่เดิม แล้วบิลด์ภาษา
