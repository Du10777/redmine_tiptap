> *Цей переклад було виконано з допомогою моделі штучної інтелігенції і його не перевіряв носій мови. Якщо ви знайдете помилку, будь ласка [відкрийте проблему або запит на внесення змін](https://github.com/Du10777/redmine_tiptap).*

Блоки коду виділяються як в редакторі, так і на збережених сторінках (питання, примітки, wiki), і вони виглядають однаково в обох. Мова блоку вибирається з бейджика в його верхньому правому кутку. Список мов визначається файлами у папці `highlight/`: один файл - одна мова.

Плагін поставляється з 52 мовами. Можна додати більше: перетворіть готову граматику highlight.js за допомогою скрипту (див. [Додавання мови з highlight.js](#додавання-мови-з-highlightjs)) або напишіть свою власну.

## Як це працює

- Виділення виконується за допомогою [highlight.js](https://highlightjs.org) (через [lowlight](https://github.com/wooorm/lowlight)). Редактор та збережені сторінки використовують той самий двигун, тому кольори збігаються.
- `_compile.sh` пакує всі файли мови в один файл, `assets/javascripts/tiptap_highlight.js`. Цей файл вже вбудований у репозиторій, тому встановлення плагіну не потребує збирання. Вам потрібно його будувати лише при зміні набору мов.
- Redmine завантажує `tiptap_highlight.js` на кожній сторінці перед редактором (`tiptap_bundle.js`). При завантаженні редактор реєструє всі мови з цього файлу.
- У редакторі блок повторно виділяється через 50 мс після припинення введення, і лише блок, який змінився. На збережених сторінках блок виділяється при прокручуванні в поле зору. Блок у згорнутому розділі виділяється при розгортанні розділу.
- Мова зберігається в збереженому HTML: `<pre><code class="language-<id>">`. Тому `id` мови ніколи не повинен змінюватися: блоки, збережені зі старим `id`, стануть звичайним текстом.
- Немає автоматичного виявлення мови: блок без мови відображається як звичайний текст. Те ж саме й блок, мова якого не в `highlight/` (наприклад, файл мови був видалений); його бейджик продовжує показувати `id`. Якщо файл мови повертається, то й кольори.
- Кольори. highlight.js позначає текст класами, такими як `hljs-keyword`, `hljs-string`, `hljs-comment`. Їх кольори встановлюються в `assets/stylesheets/src/06_code.css`, використовуючи палітру власного підсвічування синтаксису Redmine.

## Файл мови

Наприклад, `routeros.js`:

```js
import grammar from 'highlight.js/lib/languages/routeros';

export default {
  id: 'routeros',
  label: 'RouterOS',
  hint: 'MikroTik',
  keywords: 'mikrotik',
  grammar: grammar,
};
```

| Поле | Обов'язково | Що це таке |
|---|---|---|
| `id` | так | Назва мови в збереженому HTML (`class="language-<id>"`). Дозволені символи: `a-z`, `0-9`, `-`, `_`. **Ніколи не змінюйте його** після того, як блоки на цій мові були збережені. |
| `label` | ні | Назва в списку мов та на бейджику блоку. За замовчуванням - `id`. |
| `hint` | ні | Сіра примітка поряд з назвою у списку. |
| `keywords` | ні | Додаткові слова для пошуку в списку, розділені пробілами. |
| `grammar` | так | Граматика highlight.js: функція `(hljs) => language definition`. |

`label`, `hint` та `keywords` англійською мовою. Щоб показати мову під іншою назвою в інтерфейсі вашої мови або зробити її пошуковою за словами цієї мови, додайте запис у файл перекладу для цієї мови, `config/locales/<code>.yml`, під `code_languages:`. Слова там додаються до `keywords`; `label` та `hint` замінюють ті, що з файлу мови. `config/locales/ru.yml` містить приклади, правила в [config/locales/README.md](../../config/locales/README.md).

Типи файлів у папці:

- **Коротка.** Посилання на граматику з пакету npm highlight.js, як у прикладі вище; більшість мов такі. Граматика надходить від версії highlight.js, записаної в `package-lock.json` плагіну.
- **Повна копія.** Код граматики знаходиться в самому файлі й може бути відредагований. Ці файли створюються скриптом перетворення (див. нижче).
- **Власна граматика.** `log.js`, `journalctl.js`, `cisco-ios.js`; їхні спільні частини в `_common.js`.
- **Оболонка.** Готова граматика під іншою назвою: `cmd.js` - це `dos` з highlight.js, `docker-compose.js` - це `yaml`.

Файли та папки, назви яких починаються з `_`, не є мовами:

- `_compile.sh` будує мови;
- `_check.mjs` перевіряє мови під час побудови;
- `_common.js` містить спільні частини власних граматик плагіну;
- `_convert_grammar.py` - це скрипт, який перетворює граматики highlight.js (див. нижче);
- `_vendor/` містить файли, які імпортуються перетвореними мовами (створено скриптом перетворення).

Папка `README/` містить цю документацію.

## Додавання мови з highlight.js

Готові граматики (понад 190) знаходяться тут: https://github.com/highlightjs/highlight.js/tree/main/src/languages. Їх назви та псевдоніми перелічені в [SUPPORTED_LANGUAGES.md](https://github.com/highlightjs/highlight.js/blob/main/SUPPORTED_LANGUAGES.md) разом із сотнями граматик третьої сторони, що зберігаються в окремих репозиторіях. Скрипт `_convert_grammar.py` у цій папці перетворює будь-яку з них у формат плагіну.

Скрипту потрібен Python 3.6+ (без додаткових пакетів) та доступ до github.com. Запустіть його з папки плагіну:

```sh
cd /path/to/redmine/plugins/redmine_tiptap
python3 highlight/_convert_grammar.py erlang
sh highlight/_compile.sh
```

Аргумент `erlang` - це назва файлу в `src/languages` без `.js`. Друга команда будує мови й перевіряє їх. Потім перезапустіть Redmine (див. [Побудова й застосування](#побудова-й-застосування)). На Windows замість `python3` використовуйте `py` або `python`.

Приклади:

```sh
# список мов highlight.js (* = вже в highlight/), опціонально відфільтрований за словом
python3 highlight/_convert_grammar.py --list
python3 highlight/_convert_grammar.py --list sql

# кілька мов одночасно
python3 highlight/_convert_grammar.py erlang nix fsharp

# власна назва, підказка й слова пошуку (одна мова за раз)
python3 highlight/_convert_grammar.py erlang --label "Erlang/OTP" --hint BEAM --keywords "erl otp"

# замінити короткий файл, поставлений з плагіном, редагованою повною копією
python3 highlight/_convert_grammar.py routeros --force --label RouterOS --hint MikroTik --keywords mikrotik

# мова, якої ще немає у випущеній версії highlight.js, з гілки розробки
python3 highlight/_convert_grammar.py odin --ref main

# посилання на файл граматики прямо з адресного рядка браузера
python3 highlight/_convert_grammar.py https://github.com/highlightjs/highlight.js/blob/main/src/languages/odin.js

# граматика третьої сторони: посилання на її репозиторій, скрипт знаходить файл граматики
python3 highlight/_convert_grammar.py https://github.com/highlightjs/highlightjs-terraform

# локальний файл граматики
python3 highlight/_convert_grammar.py ~/grammars/mylang.js --id mylang

# короткий файл, який посилається на пакет npm замість копії коду
python3 highlight/_convert_grammar.py erlang --npm

# показати, що буде зроблено без будь-яких змін
python3 highlight/_convert_grammar.py erlang --dry-run
```

### Що робить скрипт

1. Завантажує `src/languages/<name>.js` версії highlight.js, на якій базується плагін. Версія читається з `package-lock.json` (наразі 11.12.0), тому що граматики написані для двигуна своєї версії. `--ref` вибирає іншу версію, гілку або комітру.
2. Беруть назву мови з рядка `Language:` заголовка граматики та слова пошуку з її псевдонімів (`aliases`). `id` - це назва файлу граматики.
3. Поміщає код граматики в `highlight/<id>.js` незмінений, крім експорту: `export default function(hljs)` стає `function grammar(hljs)`, а об'єкт мови `export default { id, label, keywords, grammar }` додається в кінець файлу. Якщо граматика - це модуль CommonJS (`module.exports = ...`), у верхню частину додається рядок, що оголошує `module` та `exports`.
4. Якщо граматика імпортує інші файли, завантажує їх у `highlight/_vendor/<source>-<version>/` за тими ж шляхами, що й у репозиторії, та спрямовує імпорти туди. Наприклад, `typescript` імпортує `javascript.js` та `lib/ecmascript.js`. Ці файли спільні для всіх мов з одного джерела й версії; їх редагувати не потрібно.
5. Перевіряє рядок `Requires:`, який перелічує мови, які використовуються для вбудованого коду (наприклад, `php-template` потребує `xml` та `php`). Якщо вони не в `highlight/`, виводить команду, яка їх додає. Без них вбудований код просто залишається без кольору; це не помилка.
6. Не перезаписує існуючі файли без `--force` й не приймає `id`, який уже використовується де-небудь.

Після перетворення мову можна відредагувати прямо в її файлі.

### Параметри

| Параметр | Що робить |
|---|---|
| `LANGUAGE ...` | Назва мови highlight.js, посилання на файл граматики або на репозиторій граматики третьої сторони на GitHub, або шлях до локального файлу `.js`. |
| `--ref REF` | Версія highlight.js (тег), гілка або комітру. За замовчуванням - версія в `package-lock.json`. Для посилань версія взята з посилання. |
| `--id ID` | Мова `id`. За замовчуванням - назва файлу граматики. |
| `--label TEXT` | Назва в списку та на бейджику. За замовчуванням `Language:` з граматики. |
| `--hint TEXT` | Сіра примітка у списку. |
| `--keywords TEXT` | Слова пошуку, розділені пробілами. За замовчуванням: псевдоніми граматики. |
| `--npm` | Замість копії коду напишіть короткий файл, який посилається на пакет npm highlight.js. Лише для мов самого highlight.js. |
| `--force` | Перезапишіть існуючі файли. |
| `--dry-run` | Показати, що буде зроблено без будь-яких змін. |
| `--list [WORD]` | Перелічіть мови highlight.js та граматики третьої сторони, опціонально відфільтровані за словом. |
| `--prune` | Видаліть файли в `_vendor/`, які вже не імпортуються ніякою мовою. |


**Копія чи `--npm`?** Копія показує правила в файлі: ви можете їх редагувати, використовувати граматику новішу за встановлений пакет або третьої сторони. Копія не змінюється при оновленні плагіном highlight.js; щоб її оновити, перетворіть мову знову з `--force`. Файл, зроблений з `--npm`, налічує кілька рядків, а його граматика оновлюється разом з плагіном.

## Побудова й застосування

```sh
sh highlight/_compile.sh
```

- Потребує Docker (побудова працює в контейнері `node:20-alpine`) або, якщо Docker недоступний, Node.js 18+ на тій же машині. При першому запуску скрипт встановлює пакети npm у папку `node_modules/` плагіну.
- Спочатку скрипт перевіряє кожну мову: будує її окремо, завантажує, реєструє в тому самому двигуні, який працює в браузері, та виділяє зразок тексту. Якщо мова розбита (помилка в коді, невалідний регулярний вираз, `id` вже використано), скрипт називає файл і причину й зупиняється; попередній `tiptap_highlight.js` залишається на місці.
- Потім скрипт пакує всі мови в `assets/javascripts/tiptap_highlight.js`.

Після побудови перезапустіть Redmine: він публікує файли плагіну при запуску (див. "Оновлення" в [основному BRANDU](../../docs/README.uk.md#оновлення) для команд). Браузери отримують новий файл негайно, тому що його URL містить відбиток змісту.

Якщо сервер Redmine не має ні Docker, ні Node.js, побудуйте на будь-якій машині, яка його має (копії папки плагіну достатньо) та помістіть отриманий `assets/javascripts/tiptap_highlight.js` на сервер.

## Видалення мови

Видаліть файл мови з `highlight/`, побудуйте й перезапустіть Redmine. Збережені блоки на цій мові залишаються такими, якими вони є, й відображаються як звичайний текст. Файли в `_vendor/`, які більше не потрібні, видаляються за допомогою:

```sh
python3 highlight/_convert_grammar.py --prune
```

## Власні граматики та правила редагування

- Граматика - це функція, яка приймає об'єкт `hljs` й повертає визначення мови: які частини тексту потрібно позначити й як. Посібник: https://highlightjs.readthedocs.io/en/latest/language-guide.html, довідка: https://highlightjs.readthedocs.io/en/latest/mode-reference.html. Приклади: `log.js`, `journalctl.js`, `cisco-ios.js`.
- highlight.js об'єднує регулярні вирази всіх правил мови в один й ігнорує власні прапори. Так що регістронезалежне поєднання повинно бути виписано (`[Ee]rror`) або увімкнено для всієї мови за допомогою `case_insensitive: true`.
- Надавайте перевагу стандартним класам жетонів (`keyword`, `string`, `number`, `comment`, `title`, `attr`, `variable`, `built_in`, `literal`, `meta`, `symbol`, `type` та інші): вони вже мають кольори. Клас від вас (наприклад, `scope: 'log-error'` виробляє клас `hljs-log-error`) потребує правила в `assets/stylesheets/src/06_code.css` та перебудови CSS (`assets/stylesheets/src/_build.sh`).
- Щоб запропонувати готову граматику під іншою назвою, робіть те, що робить `cmd.js`: викличте оригінальну граматику й змініть `name` та `aliases` у її результаті. Якщо псевдоніми не замінені, нова мова береться їх від оригіналу.

## Оновлення плагіну при додаванні мов

git залишає ваші файли в `highlight/` на місці. Але `assets/javascripts/tiptap_highlight.js` у новій версії плагіну вбудовується без ваших мов, і ваша побудова цього файлу перешкоджає `git pull`. Тому:

```sh
cd /path/to/redmine/plugins/redmine_tiptap
git checkout -- assets/javascripts/tiptap_highlight.js
git pull
sh highlight/_compile.sh
```

Перша команда відкидає вашу побудову, остання будує мови знову, включно з вашими. Потім перезапустіть Redmine. Якщо ви редагували файли мови, поставлені з плагіном, git може попросити вас вирішити конфлікти в них.

Якщо плагін було встановлено з архіву, збережіть ваші файли мови та папку `_vendor/` перед заміною папки плагіну, поміщіть їх назад та побудуйте мови.

## Розмір

Всі мови пакуються в один файл; браузер завантажує його один раз, а потім бере його з кешу. Наразі це 226 КБ для 52 мов. Більшість мов займають 1–10 КБ, найбільша - 1C (55 КБ).
