> *Энэ орчуулгыг хиймэл оюун ухааны загварын тусламжтайгаар хийсэн бөгөөд эх хэлтэн хянаагүй. Алдаа олбол [issue эсвэл pull request нээнэ үү](https://github.com/Du10777/redmine_tiptap).*

Кодын блокууд редакторт ч, хадгалсан хуудсанд ч (асуудал, тэмдэглэл, вики) тодруулагддаг бөгөөд хоёр газарт адилхан харагддаг. Блокийн хэлийг баруун дээд буланд байх шошгоор сонгоно. Хэлний жагсаалтыг `highlight/` хавтас доторх файлууд тодорхойлдог: нэг файл — нэг хэл.

Плагин 52 хэлтэй ирдэг. Та нэмж болно: бэлэн highlight.js грамматикийг скриптээр хөрвүүлэх ([highlight.js-ээс хэл нэмэх](#highlightjs-ээс-хэл-нэмэх) хэсгийг үзнэ үү) эсвэл өөрийнхөө грамматикийг бичих.

## Ажиллах зарчим

- Тодруулалтыг [highlight.js](https://highlightjs.org) гүйцэтгэдэг ([lowlight](https://github.com/wooorm/lowlight)-аар дамжуулан). Редактор болон хадгалсан хуудсууд ижил хөдөлгүүр ашигладаг тул өнгө нь таарна.
- `_compile.sh` бүх хэлний файлыг нэг файл болгон нэгтгэдэг: `assets/javascripts/tiptap_highlight.js`. Энэ файлыг репозиторид аль хэдийн бүтээсэн байдлаар коммит хийсэн тул плагиныг суулгахад бүтээх шаардлагагүй. Хэлний бүрэлдэхүүнийг өөрчилсөн үед л үүнийг бүтээх хэрэгтэй.
- Redmine `tiptap_highlight.js`-ийг хуудас бүр дээр, редакторын (`tiptap_bundle.js`) өмнө ачаалдаг. Ачаалагдахдаа редактор тэр файл доторх бүх хэлийг бүртгэнэ.
- Редакторт блок нь бичихээ түр зогсоосноос 50 ms өнгөрсний дараа дахин тодруулагдах бөгөөд зөвхөн өөрчлөгдсөн блок тодруулагдана. Хадгалсан хуудсанд блок харагдах хэсэгт орж ирэхэд тодруулагдана. Хураасан хэсэг доторх блок нь тэр хэсгийг нээхэд тодруулагдана.
- Хэл нь хадгалсан HTML-д хадгалагддаг: `<pre><code class="language-<id>">`. Иймээс хэлний `id`-г хэзээ ч өөрчилж болохгүй: хуучин `id`-тай хадгалсан блокууд энгийн текст болно.
- Хэлийг автоматаар тодорхойлдоггүй: хэлгүй блок энгийн текстээр харагдана. `highlight/` дотор байхгүй хэлтэй блок ч мөн адил (жишээлбэл, хэлний файлыг устгасан); түүний шошго `id`-г үргэлжлүүлэн харуулна. Хэлний файл буцаж ирвэл өнгө ч буцаж ирнэ.
- Өнгө. highlight.js текстийг `hljs-keyword`, `hljs-string`, `hljs-comment` зэрэг классаар тэмдэглэдэг. Тэдгээрийн өнгийг Redmine-ийн өөрийн синтаксис тодруулалтын палитрыг ашиглан `assets/stylesheets/src/06_code.css` дотор тохируулсан.

## Хэлний файл

Жишээлбэл, `routeros.js`:

```js
import grammar from 'highlight.js/lib/languages/routeros';

export default {
  id: 'routeros',
  label: 'RouterOS',
  hint: 'MikroTik',
  keywords: 'mikrotik',
  grammar: grammar,
};
```

| Талбар | Заавал эсэх | Энэ юу вэ |
|---|---|---|
| `id` | тийм | Хадгалсан HTML дэх хэлний нэр (`class="language-<id>"`). Зөвшөөрөгдсөн тэмдэгтүүд: `a-z`, `0-9`, `-`, `_`. Энэ хэлтэй блокууд хадгалагдсан бол **хэзээ ч өөрчилж болохгүй**. |
| `label` | үгүй | Хэлний жагсаалт болон блокийн шошго дээрх нэр. Анхдагчаар `id`-г авна. |
| `hint` | үгүй | Жагсаалт доторх нэрийн хажууд байх саарал тайлбар. |
| `keywords` | үгүй | Жагсаалтаас хайх нэмэлт үгс, хоосон зайгаар тусгаарлана. |
| `grammar` | тийм | highlight.js-ийн грамматик: `(hljs) => language definition` функц. |

`label`, `hint` ба `keywords` нь англиар бичигдсэн. Хэлийг хэрэглэгчийн интерфейсийн хэл дээр өөр нэрээр харуулахын тулд эсвэл тэр хэлний үгээр хайж олдохоор болгохын тулд тухайн хэлний орчуулгын файл `config/locales/<code>.yml` дахь `code_languages:` доор бичилт нэмнэ. Тэнд бичсэн үгс `keywords`-д нэмэгдэх бөгөөд `label` ба `hint` нь хэлний файл доторх утгуудыг орлоно. Жишээ `config/locales/ru.yml`-д бий, дүрмийг [config/locales/README.md](../../config/locales/README.md)-ээс үзнэ үү.

Хавтас дахь файлуудын төрлүүд:

- **Богино.** highlight.js-ийн npm багцад байгаа грамматик руу заасан лавлагаа, дээрх жишээн дэх шиг; ихэнх хэл ийм байдаг. Грамматик нь плагины `package-lock.json`-д тэмдэглэсэн highlight.js-ийн хувилбараас ирдэг.
- **Бүрэн хуулбар.** Грамматикийн код нь файл дотроо байх бөгөөд засаж болно. Ийм файлуудыг хөрвүүлэх скрипт үүсгэдэг (доороос үзнэ үү).
- **Өөрийн грамматик.** `log.js`, `journalctl.js`, `cisco-ios.js`; тэдгээрийн нийтлэг хэсгүүд `_common.js`-д байна.
- **Ороогч.** Бэлэн грамматикийг өөр нэрээр өгсөн: `cmd.js` нь highlight.js-ийн `dos`, `docker-compose.js` нь `yaml` юм.

Нэр нь `_` тэмдэгтээр эхэлдэг файл ба хавтсууд хэл биш:

- `_compile.sh` хэлүүдийг бүтээнэ;
- `_check.mjs` бүтээх үед хэлүүдийг шалгана;
- `_common.js` нь плагины өөрийн грамматикуудын нийтлэг хэсгийг агуулна;
- `_convert_grammar.py` нь highlight.js-ийн грамматикуудыг хөрвүүлэх скрипт (доороос үзнэ үү);
- `_vendor/` нь хөрвүүлсэн грамматикуудын импортолдог файлуудыг агуулна (хөрвүүлэх скриптээр үүсгэгдэнэ).

`README/` хавтсанд энэ баримтжуулалт байрлана.

## highlight.js-ээс хэл нэмэх

Бэлэн грамматикууд (190 гаруй) энд байна: https://github.com/highlightjs/highlight.js/tree/main/src/languages. Тэдгээрийн нэр болон өөр нэрсийг [SUPPORTED_LANGUAGES.md](https://github.com/highlightjs/highlight.js/blob/main/SUPPORTED_LANGUAGES.md)-д жагсаасан бөгөөд тусдаа репозиторуудад хадгалагддаг зуу орчим гуравдагч талын грамматик ч бас тэнд бий. Энэ хавтас дахь `_convert_grammar.py` скрипт тэдгээрийн аль ч нэгийг плагины формат руу хөрвүүлнэ.

Скриптэд Python 3.6+ (нэмэлт багцгүй) болон github.com-д хандах боломж хэрэгтэй. Үүнийг плагины хавтсаас ажиллуулна:

```sh
cd /path/to/redmine/plugins/redmine_tiptap
python3 highlight/_convert_grammar.py erlang
sh highlight/_compile.sh
```

`erlang` аргумент нь `src/languages` дахь файлын нэр, `.js`-гүй. Хоёр дахь команд хэлүүдийг бүтээж, шалгана. Дараа нь Redmine-ийг дахин эхлүүлнэ ([Бүтээх ба хэрэглэх](#бүтээх-ба-хэрэглэх) хэсгийг үзнэ үү). Windows дээр `python3`-ын оронд `py` эсвэл `python` ашиглана.

Жишээ:

```sh
# highlight.js-ийн хэлний жагсаалт (* = аль хэдийн highlight/ дотор байгаа), хүсвэл үгээр шүүж болно
python3 highlight/_convert_grammar.py --list
python3 highlight/_convert_grammar.py --list sql

# хэд хэдэн хэлийг нэг дор
python3 highlight/_convert_grammar.py erlang nix fsharp

# өөрийн нэр, тайлбар болон хайлтын үгс (нэг удаад нэг хэл)
python3 highlight/_convert_grammar.py erlang --label "Erlang/OTP" --hint BEAM --keywords "erl otp"

# плагинтай ирсэн богино файлыг засаж болохоор бүрэн хуулбараар солих
python3 highlight/_convert_grammar.py routeros --force --label RouterOS --hint MikroTik --keywords mikrotik

# highlight.js-ийн гаргасан хувилбарт хараахан ороогүй хэлийг хөгжүүлэлтийн салбараас авах
python3 highlight/_convert_grammar.py odin --ref main

# грамматикийн файлын холбоос, шууд браузерийн хаягийн мөрөөс
python3 highlight/_convert_grammar.py https://github.com/highlightjs/highlight.js/blob/main/src/languages/odin.js

# гуравдагч талын грамматик: түүний репозиторийн холбоос, грамматикийн файлыг скрипт өөрөө олно
python3 highlight/_convert_grammar.py https://github.com/highlightjs/highlightjs-terraform

# локал грамматикийн файл
python3 highlight/_convert_grammar.py ~/grammars/mylang.js --id mylang

# кодын хуулбарын оронд npm багц руу заасан богино файл
python3 highlight/_convert_grammar.py erlang --npm

# юуг ч өөрчлөхгүйгээр юу хийгдэхийг харуулах
python3 highlight/_convert_grammar.py erlang --dry-run
```

### Скрипт юу хийдэг вэ

1. Плагин ажиллаж буй highlight.js-ийн хувилбарын `src/languages/<name>.js`-ийг татаж авна. Хувилбарыг `package-lock.json`-оос уншина (одоогоор 11.12.0), учир нь грамматикууд өөрсдийн хувилбарын хөдөлгүүрт зориулж бичигдсэн байдаг. `--ref` нь өөр хувилбар, салбар эсвэл коммитыг сонгоно.
2. Хэлний нэрийг грамматикийн толгой хэсгийн `Language:` мөрөөс, хайлтын үгсийг түүний өөр нэрсээс (`aliases`) авна. `id` нь грамматикийн файлын нэр болно.
3. Грамматикийн кодыг экспортыг эс тооцвол өөрчлөлтгүйгээр `highlight/<id>.js` руу хийнэ: `export default function(hljs)` нь `function grammar(hljs)` болж, хэлний объект `export default { id, label, keywords, grammar }` нь файлын төгсгөлд нэмэгдэнэ. Хэрэв грамматик CommonJS модуль (`module.exports = ...`) бол `module` ба `exports`-ийг зарласан мөр дээд талд нэмэгдэнэ.
4. Хэрэв грамматик өөр файлуудыг импортолдог бол тэдгээрийг репозитори дахь замтай ижил замаар `highlight/_vendor/<source>-<version>/` руу татаж, импортуудыг тийш нь чиглүүлнэ. Жишээлбэл, `typescript` нь `javascript.js` ба `lib/ecmascript.js`-ийг импортолдог. Эдгээр файлыг ижил эх сурвалж, ижил хувилбарын бүх хэл хамтран ашигладаг; тэдгээрийг засах шаардлагагүй.
5. `Requires:` мөрийг шалгана; тэнд шигтгэсэн кодод ашиглагддаг хэлүүдийг жагсаадаг (жишээлбэл, `php-template`-д `xml` ба `php` хэрэгтэй). Тэд `highlight/` дотор байхгүй бол тэдгээрийг нэмэх командыг хэвлэнэ. Тэдгээргүйгээр шигтгэсэн код зүгээр л өнгөгүй үлдэх бөгөөд энэ нь алдаа биш.
6. `--force`-гүйгээр байгаа файлуудыг дарж бичихгүй бөгөөд өөр файлд аль хэдийн ашиглагдсан `id`-г авахгүй.

Хөрвүүлсний дараа хэлийг шууд өөрийнх нь файлд засаж болно.

### Сонголтууд

| Сонголт | Юу хийдэг |
|---|---|
| `LANGUAGE ...` | highlight.js-ийн хэлний нэр, грамматикийн файл эсвэл GitHub дээрх гуравдагч талын грамматикийн репозиторийн холбоос, эсвэл локал `.js` файлын зам. |
| `--ref REF` | highlight.js-ийн хувилбар (таг), салбар эсвэл коммит. Анхдагчаар `package-lock.json` дахь хувилбар. Холбоосын хувьд хувилбарыг холбоосоос авна. |
| `--id ID` | Хэлний `id`. Анхдагчаар грамматикийн файлын нэр. |
| `--label TEXT` | Жагсаалт болон шошго дээрх нэр. Анхдагчаар грамматикийн `Language:`. |
| `--hint TEXT` | Жагсаалтад гарах саарал тайлбар. |
| `--keywords TEXT` | Хоосон зайгаар тусгаарласан хайлтын үгс. Анхдагчаар грамматикийн өөр нэрс. |
| `--npm` | Кодын хуулбарын оронд highlight.js-ийн npm багц руу заасан богино файл бичнэ. Зөвхөн highlight.js-ийн өөрийн хэлүүдэд. |
| `--force` | Байгаа файлуудыг солино. |
| `--dry-run` | Юуг ч өөрчлөхгүйгээр юу хийгдэхийг харуулна. |
| `--list [WORD]` | highlight.js-ийн хэлүүд болон гуравдагч талын грамматикуудыг жагсааж, хүсвэл үгээр шүүнэ. |
| `--prune` | `_vendor/` доторх ямар ч хэл импортолдоггүй болсон файлуудыг устгана. |


**Хуулбар уу, `--npm` уу?** Хуулбар дүрмүүдийг шууд файл дотор харуулна: тэдгээрийг засаж, суулгасан багцаас шинэ грамматик эсвэл гуравдагч талын грамматикийг авч болно. Плагин highlight.js-ийг шинэчлэхэд хуулбар өөрчлөгдөхгүй; үүнийг шинэчлэхийн тулд хэлийг `--force`-той дахин хөрвүүлнэ. `--npm`-ээр хийсэн файл хэдхэн мөр урттай бөгөөд түүний грамматик плагинтай хамт шинэчлэгдэнэ.

## Бүтээх ба хэрэглэх

```sh
sh highlight/_compile.sh
```

- Үүнд Docker (бүтээлт `node:20-alpine` контейнерт явагдана) эсвэл Docker байхгүй бол тэр машин дээр Node.js 18+ хэрэгтэй. Анх ажиллуулахад скрипт npm багцуудыг плагины `node_modules/` хавтсанд суулгана.
- Эхлээд скрипт хэл бүрийг шалгана: тусад нь бүтээж, ачаалж, браузерт ажилладагтай ижил хөдөлгүүрт бүртгэж, жишээ текстийг тодруулна. Хэрэв хэл эвдэрсэн бол (кодод алдаа, буруу тогтмол илэрхийлэл, аль хэдийн авагдсан `id`) скрипт файл болон шалтгааныг нэрлээд зогсоно; өмнөх `tiptap_highlight.js` байрандаа үлдэнэ.
- Дараа нь скрипт бүх хэлийг `assets/javascripts/tiptap_highlight.js` руу нэгтгэнэ.

Бүтээсний дараа Redmine-ийг дахин эхлүүлнэ: тэр эхлэхдээ плагины файлуудыг нийтэлдэг (командуудыг [үндсэн README](../../docs/README.mn.md#шинэчлэлт)-ийн «Шинэчлэлт» хэсгээс үзнэ үү). Браузерууд шинэ файлыг шууд авдаг, учир нь түүний URL агуулгын хурууны хээг агуулдаг.

Хэрэв Redmine сервер дээр Docker ч, Node.js ч байхгүй бол тэдгээрийн аль нэг нь байгаа дурын машин дээр бүтээгээд (плагины хавтасны хуулбар хангалттай), гарсан `assets/javascripts/tiptap_highlight.js`-ийг серверт байрлуулна.

## Хэл устгах

Хэлний файлыг `highlight/`-аас устгаж, бүтээгээд, Redmine-ийг дахин эхлүүлнэ. Энэ хэлээр хадгалсан блокууд хэвээр үлдэж, энгийн текстээр харагдана. `_vendor/` дахь хэрэггүй болсон файлуудыг дараах командаар устгана:

```sh
python3 highlight/_convert_grammar.py --prune
```

## Өөрийн грамматик ба дүрмийг засах

- Грамматик нь `hljs` объектыг хүлээн аваад хэлний тодорхойлолтыг буцаадаг функц: текстийн аль хэсгийг яаж тэмдэглэхийг заана. Гарын авлага: https://highlightjs.readthedocs.io/en/latest/language-guide.html, лавлах: https://highlightjs.readthedocs.io/en/latest/mode-reference.html. Жишээ: `log.js`, `journalctl.js`, `cisco-ios.js`.
- highlight.js хэлний бүх дүрмийн тогтмол илэрхийллүүдийг нэг болгон нэгтгэж, тэдгээрийн өөрийн флагуудыг үл тооно. Иймээс том, жижиг үсгийг ялгахгүй тулгалтыг тодорхой бичих (`[Ee]rror`) эсвэл бүх хэлэнд `case_insensitive: true`-ээр идэвхжүүлэх хэрэгтэй.
- Стандарт токен классуудыг (`keyword`, `string`, `number`, `comment`, `title`, `attr`, `variable`, `built_in`, `literal`, `meta`, `symbol`, `type` гэх мэт) илүүд үзээрэй: тэдгээр аль хэдийн өнгөтэй. Өөрийн класс (жишээлбэл, `scope: 'log-error'` нь `hljs-log-error` классыг үүсгэнэ) `assets/stylesheets/src/06_code.css` дотор дүрэм, мөн CSS-ийг дахин бүтээхийг (`assets/stylesheets/src/_build.sh`) шаардана.
- Бэлэн грамматикийг өөр нэрээр санал болгохын тулд `cmd.js`-ийн адил хийнэ: эх грамматикийг дуудаж, үр дүн дэх `name` ба `aliases`-ийг өөрчилнө. Хэрэв өөр нэрсийг сольж өгөөгүй бол шинэ хэл тэдгээрийг эхнийхээс нь авна.

## Хэл нэмсэн бол плагиныг шинэчлэх

git `highlight/` дахь таны файлуудад хүрэхгүй. Харин плагины шинэ хувилбар дахь `assets/javascripts/tiptap_highlight.js` нь таны хэлүүдгүйгээр бүтээгдсэн бөгөөд энэ файлын таны бүтээсэн хувилбар `git pull`-д саад болдог. Иймээс:

```sh
cd /path/to/redmine/plugins/redmine_tiptap
git checkout -- assets/javascripts/tiptap_highlight.js
git pull
sh highlight/_compile.sh
```

Эхний команд таны бүтээснийг устгаж, сүүлийнх нь таны хэлүүдийг оролцуулан хэлүүдийг дахин бүтээнэ. Дараа нь Redmine-ийг дахин эхлүүлнэ. Хэрэв та плагинтай хамт ирсэн хэлний файлуудыг засварласан бол git тэдгээр дэх зөрчлийг шийдвэрлэхийг хүсч магадгүй.

Хэрэв плагиныг архиваас суулгасан бол плагины хавтсыг солихын өмнө өөрийн хэлний файлууд болон `_vendor/` хавтсыг хадгалж, дараа нь буцааж тавиад, хэлүүдийг бүтээнэ.
